### Заполнение пропусков

![alt text](/notes/images/image.png)

Пропустить и удалить данные, в которых есть пропуски - самый простой способ, но в это случае множество данных может быть утеряно. Тогда нужно выработать метод заполнения пропусков **missing data imputation**.

**Заполнение в категориальных или бинарных признаках осуществляется с помощью (т.е. значение признака принимает одно из К значений):**

1. Мода распределения
2. Новая категория "пропуск". Если пропусков много, то тогда можно использовать.

Также можно обучить классификатор, который будет предсказывать пропущенное значение на основе не-пустых значений.

**Заполнение пропусков в вещественных признаках осуществляется:**

1. Выборочной медианой (более устойчива к выбросам, т.к. она не зависит от суммы)

2. Выборочное среднее. На практике часто не следует использовать и лучше решать задачу регрессии для предсказывания возможного пропущенного результата.

#индикатор_пропуска Можно добавлять для признаков, которые были предсказаны с помощью другой модели (классификатор или линейная регрессия), для первых - вероятность класса, для вторых - стандартное отклонение, которые будут говорить с каким уровнем надежности был предсказан признак.

программные средства заполнения пропусков:

1. с помощью усреднения k-ближайших соседей. Для поиска ближайших соседей используется метрика евклидового пространства, для каждого объекта с пропуском находятся объекты с похожими признаками. Отсутствующее значение заменяется средним значением соседей (соседи могут иметь одинаковый вес (uniform) или вес, зависящий от расстояния(distance))

```python
from sklearn.impute import KNNImputer
nan = np.nan
imputer = KNNImputer(n_neighbors=2, weights="uniform")
imputer.fit_transform(df)
```

2. Поддержание одинакового количества признаков путем заполнения их значением 0:

```python
imputer.set_params(keep_empty_features=True)
imputer.fit_transform(X)
```

3. Медиана, среднее и тд:

```python
from sklearn.impute import SimpleImputer
imp_mean = SimpleImputer(missing_values=np.nan, strategy='mean')
```

### Обработка временного признака

Если известна только дата, то можно закодировать признак как число дней с момента наблюдений, если известно еще и время - то число секунд с момента наблюдений.

Временной признак позволяет учесть тренд (рост/падение популярности с течением времени). Помимо этого можно учитывать еще и сезонность, что позволит получить более точно аппроксимировать значения. Сезонность можно выделять номером дня/недели/месяца и тд. Также можно просматривать внутредневную сезонность (номер часа).

### Кодирование категориального признака (Эмбеддинг)

1. Порядковое кодирование #ordinal_encoding (кодируем признак по тому порядку, который представлен по умолчанию в df). **Не рекомендуется использовать**, т.к. модель при обучении будет учитывать порядок, тогда как нумерация на самом деле была произвольная + будет ложное представление о близости значений.

2. Частотное кодирование #frequency_encoding (кодируем в зависимости от частоты признака среди всего количества признаков, например, Хлеб - 1/3, Сыр - 1/3, Хлеб - 1/3). Полезность определяется в зависимости от того, наксколько частота встречаемой категории связана с целевой переменной.

3. Однократное/фиксированное кодирование #one-hot_encoding, #dummy encoding (признак кодируется вектором размера К дискретных значений). Например, Хлеб - [0, 0, 1], Сыр - [0, 1, 0]. Из плюсов - кодирование признаков однозначное, т.к. попарное расстояние между признаками одинаковое. Минус кодировки - при большом количестве признаков вектор становится слишком большим. Но это можно нивелировать минусы путем **регуляризации**.

4. Кодирование средним #mean encoding, #target encoding (признак кодируется средним ожидаемым откликом в рамках одной категории). Для регрессии находим средние значения в рамках одной категории, для классификации среднее находим в рамках частот. Такой способ **максимально информативен для предсказывания отклика по кодировке**. **Вместе с этим подобная кодировка ведет к переобучению модели**, тк мы фактически указываем моделе какие результаты мы должны получить. Это можно нивелировать при помощи #leave_one-out_encoding - кодирование признака осуществляется средним в рамках одной категории, **не учитывая при этом значение того признака для которого высчитываем target**. + можно кодировать категорию средним значением по другой категории, чтобы максимально избежать зависимостей.
